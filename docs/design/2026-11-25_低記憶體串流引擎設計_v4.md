# h3.c 低記憶體串流引擎設計 v4（2026-11-25）

用戶硬性目標：在「可用 RAM 約 30GB（Strata 在線、不得停）」條件下，用**完整 34GB int8 convrot DiT**（非 pruned）完成影片生成；引擎記憶體預算 24GiB，依實測調整；達不到就回報實測瓶頸與最低記憶體需求，不得假報 PASS。

## 1. 設計原則（對應用戶十點）
1. **mmap 按需讀**：safetensors 改 `mmap(MAP随机)+madvise(MADV_RANDOM)`，張量視窗讀完即 `munmap`/丟棄頁，禁止整檔 read 進 malloc。
2. **INT8 常駐格式**：convrot int8 權重以 I8(+scale/U8 comfy_quant sidecar) 原格式進 GPU buffer；禁止整體展開回 BF16（現有 `use_slower_*` 展開路徑僅留給對拍驗證）。
3. **Fused dequant+matmul kernel**：MSL 內把 int8 子塊在 shared memory 內反量化→bf16 張量核直乘（或 native int8 tensor-core 路徑），消滅整層 dequant 中間張量；先在 512³ 單測對拍 CPU int8 參考。
4. **逐層串流 + 預讀 + 雙緩衝**：50 個 DiT block 每 block int8 ≈ 0.62G。GPU 常駐視窗 = 計算中 block N + 雙緩衝 block N+1（≈2×0.62G 活動）＋固定小件（embeddings/AdaLN 首層表/heads）；SSD→host→GPU 上傳與 block N 計算重疊（async MTLCommandQueue + ring buffer）。層輸出只需單 block 寬。
5. **階段生命週期**：TE bf16（串流過一遍，峰值窗口 ≤4GiB）→ 釋放全部 TE buffer → DiT（視窗 ≤8GiB 權重 + activation）→ 釋放 DiT → VAE（tile ≤10GiB）→ 釋放。任何時刻 GPU live = 單階段峰值。
6. **分塊與 buffer 複用**：全域 buffer arena（階梯式重用同一批 Metal buffer：TE 用完的 slab 供 DiT activation、DiT 用完的供 VAE tile）；sol-attn/SelfLift/VAE 全部分塊，塊大小按 24GiB 預算反推，不逐次 new。
7. **24GiB 預算分解（初值，依實測調）**：TE ≤4｜DiT 視窗 ≤8｜activation(含 sol 選块元數據) ≤4｜VAE tile ≤10｜重疊安全邊際 ≥2。各階段峰值互斥，理論上界 14–16GiB，雙倍安全裕度內。
8. **不依賴 swap / 不動 Strata**：沿用 e0 護欄監控（swap>45G 或 free<12% 或 Strata health 連續失敗 → SIGTERM h3 並記錄）；每次 run 記錄 Strata RSS 漂移（要求 <2G）與 `vm.swapusage` 增量。
9. **實測儀表（每 run 輸出 JSON）**：分段 wall/GPU 使用率（`root-gpu=` profile 既有）、Metal peak/alloc、host RSS、swap 增量、**SSD 讀取量**（每階段 pread/mmap 觸發字節計數器，設計新增 `h3_io_stat`）、每步去噪時間、成片帧抽查。
10. **文件先行 + 每步推 Git**：本文件為 v4 基準；實作里程碑 M3–M7 各自綁驗收命令與 PASS/FAIL 判據，完成即 push（權重/影片不入 Git）。

## 2. 帶寬與時間模型（估算，M3.5 後用實測替換）
- 完整 int8 權重 ≈ 33G；每去噪步完整前向一次 = 讀 ~33G（sol-attn 稀疏不減權重讀取，只減 activation/KV 計算）。
- 外接 SSD2T 帶寬實測目標：先跑 `dd if=大檔 of=/dev/null` 量Sequential（估 1.5–3GB/s，未知）→ 串流下限 11–22s/step；雙緩衝重疊後 SSD 開銷大部分藏進計算。
- 1344×768×124f latent ≈ 12–13 萬 token：int8 稠密 fwd 估算單步 5–10 分鐘（M5 Max 矩陣吞吐上限），**sol-attn 稀疏化（τ 排程、首 2 層 dense）是讓單步降到 ~40–60s 的必要條件**；若 sol-attn 修不好，退路 = FastH3-4step 蒸餾 LoRA + 小解析度 draft（設計 v3 兩段式），仍守住 24GiB。
- 對照基準：O87(RTX4060 8G，串流) 305s、ODA 142.9s。本機合理目標區間（FACT 推導）：6-step 全尺寸 4–8 分鐘級；若 sol 稀疏生效 + 4-step draft 則可壓至 2–4 分鐘。

## 3. 里程碑綁驗收（對應任務登記）
- **M3 sol-attn 語義對齊**（進行中）：τ=1.3、min 12288、extra 256、start 0.2、centering-K、colmean、pooled tail（O87 patches 參數）+ degen 根因修復；驗收 = 小尺寸 degen 與 exact 對拍 ≤容差 + 出片結構正確（vision 覆核）。FAIL 則記錄參數掃描表。
- **M3.5 loader 串流化 + fused dequant**：mmap 載入、convrot int8 直載（含 comfy_quant sidecar 解析、pruned 與原件兩格式、NVFP4-AWQ TE、bf16 LoRA、int8 sol_vae 全部走同一 loader）；驗收 = 512³ 對拍 CPU 參考最大絕對誤差表 + 「整檔 malloc」消失（RSS/計數器證據）。
- **M4 完整 34G 端到端（小尺寸）**：O87 原件或自製轉換 int8，seed/prompt/參考圖 = Git 內固定資產；驗收 = 成片 + 記憶體表（peak ≤24GiB、swap 增量 <2G、Strata 不掉線）。原件未到時先跑自製轉換版並如實標註來源。
- **M5 SelfLift(0.4, transition 3) + upscaler fp16**：global_stream 4096 分塊；驗收 = 兩段拼接無縫 + 逐段計時。
- **M6 sol_vae int8 tiled 解碼 + Metal 原生 conv**：修復 MPSGraph conv 導入失敗根因（error=100000002 線索：MSL 自寫 conv 或 im2col 優化）；驗收 = VAE decode ≤8s（現 32s）+ 像素對拍。
- **M7 全規格 1344×768×124@24fps**：CFG1.0、6-step、真實影片；驗收 = 無鬼影/塗抹/人物穩定（vision 覆核關鍵幀 1:1 對歌詞規格不適用於此，套用配方驗收標準）+ 性能報告對照 305s/142.9s + 最低記憶體需求聲明。
- 任一里程碑 FAIL：給出實測瓶頸曲線（帶寬 vs 視窗大小 vs 每步時間）與最低記憶體需求，不假報 PASS。
